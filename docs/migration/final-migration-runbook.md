# Laravel-to-Go Migration Runbook

This runbook is the reviewed source of truth for the final migration gate
(issue [#194](https://github.com/ifuschini/idelium-api-go/issues/194)). It
does not enable production traffic; the generated gate manifests remain the
authority for whether a stage is ready.

## Ownership and feature flags

1. Resolve route ownership from
   [`migration-ownership-matrix.json`](../contracts/migration-ownership-matrix.json)
   and apply only the explicit overrides in
   [`route-rollout-overrides.json`](../contracts/route-rollout-overrides.json).
2. The gateway is the only switch. Keep `fallback_owner: laravel` and
   `dual_writes_allowed: false` in
   [`route-switch-gates.json`](../operations/route-switch-gates.json).
3. Promote a Go-owned route through `release-candidate`, `dark-deployment`,
   `canary`, `partial`, `majority`, and `complete`; do not change a route's
   flag while an aggregate still has a Laravel writer.

## Cutover procedure

Before each promotion, record the source/target immutable image digests,
gateway revision, named approvers, baseline and candidate metric windows, and
links to the required redacted evidence. Run the applicable Web, CLI, runner,
and Docker smoke suites, then observe the stage for the period in
[`route-switch-gates.json`](../operations/route-switch-gates.json).

The staging manifest is generated by
[`build_staging_route_cutover.py`](../../scripts/build_staging_route_cutover.py)
and must report zero blockers before production is enabled:
[`staging-route-cutover.md`](../contracts/staging-route-cutover.md).

## Observability and stop conditions

Use correlation IDs and redacted dashboards only. Stop promotion and trigger
the rollback plan for any cross-tenant access, credential exposure, lost or
duplicate write, side-effect mismatch, consumer smoke failure, readiness loss,
or threshold breach. The thresholds and evidence checklist are maintained in
[`route-switch-gates.json`](../operations/route-switch-gates.json), including
5xx, authorization-denial, p95 latency, and observation windows.

## Rollback to Laravel

Execute the ordered steps in
[`rollback-rehearsal.json`](../contracts/rollback-rehearsal.json): freeze
forward rollout, switch the gateway to Laravel, restore the Laravel image,
resume workers and scheduled jobs, run smoke checks, and preserve redacted
evidence. Rollback never performs reverse application replay or a database
restore. The rehearsal must be successful before production promotion.

## Legacy retirement criteria

Retire Laravel fallback only after the `complete` stage has passed its 24-hour
observation window, all route and consumer smoke checks are green, no stop
threshold has fired, and the rollback rehearsal evidence is recorded. Then
open a separate ADR for removing fallback routes, legacy bridge credentials,
or backward-compatible schema. Until that ADR is approved, keep Laravel
available as the documented fallback.

## Verification

Regenerate and validate all manifests before review:

```sh
python3 scripts/build_staging_route_cutover.py --check
python3 scripts/build_rollback_rehearsal.py --check
python3 scripts/build_operations_handover.py --check
python3 scripts/validate_route_switch_gates.py
```

These checks are also part of `make verify`; their output and the relevant CI
run are the evidence links attached to the migration issue.
